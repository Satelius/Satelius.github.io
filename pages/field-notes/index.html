001 LOCAL / GUIDE

HOW TO EXTEND THIS WEBSITE / 使用说明

建立你的第一条档案

这不是占位页面。它既是站点的使用手册，也是一个可以直接复制、改名并继续写作的独立页面样板。

作者 SATELIUS 发布 2026.08.14 阅读约 4 分钟 无需 JAVASCRIPT

先说结论

新增内容只需要两件事：复制一个页面目录，再向 assets/pages-data.js 增加一条记录。没有构建步骤，也没有隐藏配置。

01

STRUCTURE / 结构

一个页面，就是一个能独立搬走的目录。

站点只依赖浏览器原生能力。首页负责展示索引，子网页保存在 pages/ 下，每个目录都有自己的 index.html。共享视觉资源放在 assets/ 中。

personal_web/
├── index.html
├── 404.html
├── assets/
│   ├── favicon.svg
│   ├── pages-data.js    ← 唯一的索引元数据文件
│   ├── site.js
│   └── styles.css
└── pages/
    └── field-notes/
        └── index.html   ← 你正在阅读的页面
PATH RULE / 路径规则

子网页引用共享资源时使用 ../../assets/...。这种相对路径在 GitHub Pages、自建静态服务器和本地预览中都能工作。

02

COPY / 复制

复制样板，然后只改真正属于页面的内容。

例如要新增一个名为 reading-list 的页面，可以在项目根目录执行：

Copy-Item -Recurse .\pages\field-notes .\pages\reading-list

打开新目录里的 index.html，至少修改标题、摘要、canonical 地址、正文和文章日期。保留顶部返回链接与共享资源路径，即可维持一致的导航和视觉语言。

目录名要稳定

推荐使用小写英文和连字符，例如 reading-list、photo-log。发布后不要随意改名，因为目录名就是公开 URL 的一部分。

03

REGISTER / 登记

所有索引元数据，只在一个文件里维护。

编辑 assets/pages-data.js，向数组追加对象。首页会自动生成条目、分类按钮、搜索文本与总数。

{
  id: "reading-list",
  number: "003",
  label: "READING LOG 003",
  title: "近期阅读记录",
  href: "./pages/reading-list/",
  external: false,
  category: "笔记",
  year: "2026",
  date: "2026-08-14",
  summary: "关于近期阅读、摘录和延伸线索的持续记录。",
  tags: ["阅读", "摘录", "笔记"],
  accent: "#dfff00"
}

外链使用完整的 https://... 地址，并把 external 设为 true。其他字段完全相同，不需要为外链另写模板。

04

CHECK / 检查

先在本地验证，再把文件交给 GitHub Pages。

  1. 启动静态服务器在项目根目录运行 python -m http.server 8000。
  2. 打开首页访问 http://localhost:8000/，确认新条目可见且筛选正常。
  3. 检查独立地址直接访问新目录 URL，刷新页面并测试返回链接。
  4. 关闭脚本复查禁用 JavaScript 后，首页仍应提供核心入口，子网页正文应保持完整。
NO BUILD / 没有构建

GitHub Pages 直接发布这些文件。项目根目录的 .nojekyll 会明确跳过 Jekyll 处理。
