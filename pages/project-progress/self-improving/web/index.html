让失败不再白费

ASPIRE 的关键不是“训练一个更大的机器人模型”，而是让 coding agent 写程序、看执行错误、修程序，再把验证过的修复沉淀成可复用技能。

我们的问题：这套方法能不能迁移到仿真环境生成，让穿模、重叠、噪点、 物理不稳定等失败也逐渐变成可复用经验？

01 · 背景

机器人失败，难点往往不是“再试一次”

任务只返回成功或失败时，我们不知道问题出在看错、抓错、规划失败，还是控制执行失败。 更麻烦的是，任务结束后这些修复经验通常被丢掉。

A

反馈太粗

只有最终 0/1，无法定位应修改感知、规划、抓取还是控制。

B

经验不积累

第 100 个任务仍可能从零调试，之前发现的恢复办法没有留下来。

C

单路线易卡住

沿着一个错误思路反复微调，容易陷入局部最优。

02 · 方法

ASPIRE 的三个部件，组成一个非梯度闭环

搜索对象是可执行的 Python 机器人程序，不是神经网络权重。 Agent 负责提出和修改程序，执行器负责真正调用机器人 API，验证结果决定什么能留下。

01

Robot Execution Engine

把感知、抓取、规划、控制 API 暴露给程序，并在 primitive 附近记录输入、输出、异常和可用图像。

让错误可定位
02

Skill Library

把验证过的修复压缩成“失败特征 → 何时使用 → 如何修复”，供后续任务检索。

让经验可迁移
03

Evolutionary Search

每轮生成多个机制不同的候选，在同一 debug seeds 上比较，从 Top-3 继续探索。

让搜索更有多样性

执行引擎里有 baseline 策略吗？

没有隐藏的整任务 baseline policy。 引擎提供固定的 IK、关节运动、夹爪和感知 API；任务级动作顺序来自 agent 写的程序。 搜索有初始程序 P0，论文也有实验对照，但它们都不是 execution engine 内置的任务策略。

06 · Insight / Idea

把“环境生成失败”也变成 Skill

ASPIRE 沉淀的是机器人程序的修复模式。对应到我们的项目，可以沉淀 环境错误的条件化修复模式：不是记住某个场景答案，而是记住“遇到什么现象， 在什么条件下，哪类有限修复经过了什么验证”。

失败长什么样 failure signature 错误码、对象关系、局部几何、trace
+
什么时候适用 context 资产类型、任务、版本、阈值
+
可以怎么修 bounded repair 小而明确的参数或结构变换
+
为什么可信 validation receipt debug seeds、clean controls、反例

环境噪点 / 碎片

积累“什么噪声模式 → 哪种滤波、网格清理或重建参数”，同时保留误删反例。

穿模 / 重叠

积累目标局部坐标下的重求解、碰撞余量和最小位移策略，避免写死绝对坐标。

接触 / 支撑不稳定

积累足迹、支撑余量、settle 后漂移与替代资产的条件化修复。

资产 / 证据不完整

积累缺失资产恢复、版本约束、内容哈希与 package → run → media 绑定检查。

环境版 evolutionary search

不要只沿一个修复方向反复微调

对同一失败生成 K 个机制不同、幅度受限的候选；先过确定性静态门， 再在相同 debug seeds 上执行，保留 Top-3，最后只用 held-out 物理验证决定是否晋升。

→

→

held-out 通过Skill
01

Agent 只提案，validator 才裁决。不能让语言模型覆盖确定性物理门。

02

先过多 seed + clean controls。一次成功不能晋升为技能。

03

Held-out 期间只读。不能边看测试答案边改技能库。

04

技能要有版本、反例和退役机制。旧经验可能过时或过度特化。

07 · 下一步

下一轮要回答：它是否真的改善物理生成？

从“合成机制可行”推进到“真实仿真有效”，需要一组预算一致、证据独立的实验。

01

失败样本结构化

定义 FailureEpisode：输入身份、错误签名、候选修复、验证回执、反例和生命周期。

02

受限修复接口

先开放少量可审计动作，如重定位、调整余量、换资产、局部网格修复。

03

真实 SAPIEN 三臂 A/B

同一预算比较 frozen、当前 trace repair、validated memory + search。

04

晋升与退役

只有 held-out 物理成功提升、unsafe publish 为 0、clean regression 为 0 才保留。

Keep rule held-out 物理完成率 ↑ · unsafe publish = 0 · clean regression = 0 · 预算有界

ASPIRE × Gen-Env

一句话带走

先把失败变成可归因的证据，再把经过独立验证的修复变成技能； 搜索可以更大胆，但发布门必须更严格。
