02 / 为什么会有顿挫

目标可以瞬间换，
机械臂需要时间跟上。

把元动作想成方向键：向前 → 向左 → 向上。每个词先变成一个目标位置，底层控制器再驱动机械臂追过去。

目标变化很快、动作又频繁换方向时，真实运动会受跟踪响应和已有速度影响，视频里就可能看到“一顿一顿”。

这次改的是目标怎样推进，不把问题简单归因于“用了 token”。

元动作执行链 · 职责示意

MV_FWD→MV_LEFT→MV_UP
解释器：本条动作要去哪里
↓
目标参考：怎样推进到那里
↓
原生 IK 与控制器：让关节跟随

目标位置 ≠ 此刻的实际位置。smooth 改动后，实际运动仍要靠物理执行验证。

03 / 为什么要让动作 smooth

让动作更可控，
也让后续复用更清楚。

我们希望在把任务做完的同时，减少不必要的猛冲、回摆和接触扰动。smooth 研究关心的是实际执行过程。

01

让机械臂更容易跟上目标

目标突然换到远处，机械臂就要追赶；频繁换方向，可能带来过冲或回摆。平缓交接目标，是为了减少这种突变带来的运动尖峰。

02

给抓持和搬运少添扰动

抓住方块后，突然加速或换向会改变夹爪与物体间的受力。我们希望少一些不必要的扰动，让接触过程更容易控制。

03

让动作词有可复用的走法

把平滑放在共用执行层，教师和未来TacJev仍只需选择元动作；由同版本解释器展开，便于对照、复现和定位执行误差。

动机与证据分开看：本轮已测到共同搬运段的加速度／jerk 指标（p95）降低，并取得同开局两条 ON 成功参考。抓持稳定性是否提高、能否推广到更多开局，还需要专门验证。

smooth 改善的是执行方式；能否完成任务，仍取决于选对动作、跟踪效果和必要的收尾。它不保证ON／OFF每步实态相同或自动成功。

04 / 借鉴 Show-Harness 的 smooth 插件

把“突然指到终点”，
换成一串逐步推进的路标。

像端着一杯水：轻起步，中间前进，接近终点时轻收尾。插件给出的是移动进度表；控制器把进度换成中间目标。

原理示意 · 非实测轨迹
匀速参考0%

起点、终点明确，路径仍由解释器确定。

02 / 再定节奏

03 / 交给控制器

发出准确末参考，不等于实体已经到位。

展开一行公式与来源

归一化时间 u 从0到1；零起末参考速度时，移动比例 s(u) = 10u³ − 15u⁴ + 6u⁵。中间目标 = 起点 +（终点 − 起点）× s。我们复用的插件来自 Show-Harness 固定版本源码。上游另支持有条件的速度衔接；本轮只验证目标缓动。

05 / 在 TacHarness 中放在哪里

动作词不变，
在“目标”和“IK”之间加一个开关。

元动作向前 / 向左 / 向上
→
解释器确定本条目标
→
smooth 开关安排中间参考
→
原生 IK / 控制执行并记录实态

复用原有的四个物理子步

一个移动 token 仍是 20ms，内部本来就有四个 5ms 物理步。开启后，在这些时刻逐步交接参考，不额外增加本条动作的执行帧。

接续的是参考目标

每段移动的第一步直接执行；GRASP / RELEASE 保留原夹爪命令，并清除移动继承，避免把抓放混进移动缓动。

本轮没有开启跨 token 保速；也不保证 ON / OFF 每一步的实际起终点相同。

08 / 怎样判断“更顺”

同一段搬运动作，
运动变化的尖峰更低了。

只比较双方共同的1秒搬运区间（控制索引136–185），用200Hz真实TCP位置计算；新增收尾没有混入统计。

加速度 p95↓27.74%

54.948 → 39.707 m/s²

jerk p95↓54.71%

11050.480 → 5004.770 m/s³

jerk，用人话说

就是“加速度变化得有多猛”。更低的尖峰支持运动变化变缓；它不是肉眼抖动幅度，也不是任务成功率。

p95：95%的采样值不超过这个数。橙色为OFF，绿色为ON；原始数据未做滤波。

进展成立，局限也要留下

公共搬运段总体改善，同向接续组的部分指标仍变差，顿挫没有全部消失。

两条ON是同开局复验，尚不能推为跨开局成功率；本轮验证的是固定元动作参考。
