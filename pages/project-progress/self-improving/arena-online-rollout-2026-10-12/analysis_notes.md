# Arena 在线 rollout：中文说明与叙事核查

说明日期：2026-10-12，Asia/Shanghai。本页只读已有源码与原件，不新增 API 请求、推理、原生运行或研究实验。原始证据来源：`outputs/collections/tacjev-first/online-resume-20261012T014737Z/`。

## 一句话说明这次到了哪里

这次接通并验证了“机器人拍三张当前图 → 在线多模态教师选一个动作词 → 动作解释器执行 → 拍下一组图”的真实闭环。机器人确实由在线模型控制；模型每次看到的是刚执行完上一动作后的新图。然而，两次尝试都没有碰到方块，也没有把方块送到目标。因此，在线采集链路和一次正式配对案例验证已完成，合格示范为零，候选控制参数没有采纳。

“链路完成”与“任务成功”是两件分别验收的事。好比已确认驾驶员能看到路、发出方向指令、车辆会执行、全程有录像；这并不证明车辆已经驶达终点。这次两层都检查了，前者通过，后者失败。没有训练 TacJev，也没有证明学生策略能力。

## 要做的任务是什么

环境标识是 Arena `lift_object`，物体是 `dex_cube`，本体是 Franka 机械臂加双指触觉夹爪。名字里虽然有 lift，实际完整任务并非仅把物体抬起来：

> Grasp the cube and move it to the displayed target position.

中文意思：“抓住方块，把它移动到画面显示的目标位置。”场景中的彩色坐标轴标记表示目标。方块自身也有颜色，不应把两者混为一物。

本次开发开局的原生目标位置约为世界坐标 `(0.597544, 0.162933, 0.400920)` 米。成功判定检查的是**方块**到目标的空间距离是否小于 0.05 米。仅移动夹爪、出现触觉接触、教师返回 `DONE`，都不能代替原生成功判定。目标的精确数值保存在控制与审计资料中，没有交给动作教师。

## 分工：谁选动作，谁把动作变成运动

- **编排 Agent**实现采集流程、检查证据、提出并登记一次参数调整，还负责预算和对照。它不在每次教师决策里用物体真值替教师选 token。
- **在线多模态教师**看到三图、完整任务及最多五个移动 token，返回九个合法元动作之一。服务返回的型号是 `gpt-6.1-sol`。这是服务声明的身份，未独立核验模型权重。
- **动作解释器**把动作词变成一小段相对位姿 IK 控制。它读机械臂当前末端位置与姿态，计算控制误差；不会根据方块真值自动规划抓取位置。
- **原生环境与记录器**推进物理、给出真实成功信号，保存动作后的帧、状态和触觉。**DataEngine**把保存的数据作为只读目录和回放展示，不负责改变原生结果。

## 一次决策里模型到底看到了什么

模型可见观测固定为以下内容：

1. 场景图：RGB，640 × 360，看到机械臂、桌面、方块及目标标记。
2. 腕部图：RGB，640 × 360，跟随机械臂的局部视角。
3. 双指触觉拼图：RGB，384 × 576，上面是左指，下面是右指。
4. 完整任务英文原文。
5. 最近最多五个**已执行移动 token**，最新动作放在最前面。
6. 固定 system 提示词与 `prompt_version`。

每次实际请求是独立的 `chat_completions` 请求：一条固定 system message，加一条包含当次文字与三张 PNG 的 user message。`temperature=0`，三张图的 `detail=high`。不是完整会话；没有把前 49 轮的图片、回答或推理全文带入第 50 轮。也没有 `previous_response_id` 或线程记忆。

模型没有收到机械臂精确 pose、关节角、方块/目标精确坐标、数值接触力、原生 reward/success、解释器数值步长、hold 数或控制频率。它只知道“朝固定方向的目标作有界控制，实际运动可能小于要求”。A/B 的 step 与 clamp 数值没有写进模型提示词，教师只能从后续新图观察不同的实际响应。

这次全部 100 个决策的触觉 PNG 是同一张全黑图，哈希一致。第三图确实发送并保存了，黑色符合已有“无接触各字段归零”合同；不是漏图。由于夹爪始终没有接触方块，这张图没有提供抓取受力变化，也没有形成接触后触觉策略能力的验证。

这里“历史”非常窄：只记六种移动 token；`GRASP`、`RELEASE` 和 `DONE` 不进入这五个位置。因此 B 的第 12 个编号决策（`decision_000012`）发生在 GRASP 之后，但 user 里的移动历史仍是 `MV_DOWN, MV_FWD, MV_FWD, MV_FWD, MV_FWD`，与 GRASP 决策的移动历史相同。夹爪是否闭合要靠当前图观察，不能从这串历史直接知道。这个输入设计是已确认合同，本次没有改动。

原始 `request.json` 保留了完整提示词、user 字符串及三张图的 PNG base64，是这次请求真实发送的请求体。可以从它直接解码并展示当次图片；不应从动作后的帧冒充动作前输入。

模型输出被要求只有一个动作 token，不得带解释或标点。网页可以展示真实记录的输出 token 和安全响应回执。完整原始 HTTP 响应正文没有保存，仅留下其 SHA-256 及经过安全处理的字段，因此不能把安全回执称为“原始 HTTP 响应全文”。没有模型理由或思维链可供查看。

## 九个动作词怎样映射到控制

方向全部使用**机器人基座坐标系**，不是图片里的上下左右。`MV_FWD` 是 +X，`MV_BACK` 是 −X，`MV_LEFT` 是 +Y，`MV_RIGHT` 是 −Y，`MV_UP` 是 +Z，`MV_DOWN` 是 −Z。图片经过透视投影，画面里的“左边”不一定等于机器人 +Y。

每个移动 token 开始时，解释器以当前末端位置为起点，沿对应轴增加一次步长，得到一处固定目标。A 的目标偏移为 25 mm；B 为 120 mm。接下来五个控制帧向**这同一处目标**作反馈控制，不是每帧重新增加 25/120 mm，更不是一个 token 保证移动五倍步长。

每一控制帧实际做以下事：

1. 读当前末端位置与姿态。
2. 计算到固定位置目标、固定朝下姿态的误差。
3. 平移误差逐轴限幅（A 每轴最多 0.025 m，B 最多 0.12 m）；旋转误差逐轴最多 0.08 rad。
4. 六个误差分量除以实际控制器 scale `0.5`，再拼上夹爪目标，得到七维动作。
5. 将该动作交给原生相对位姿 IK 控制器，推进环境一次，再保存真实结果。

七维动作的意义是 `[x相对控制, y相对控制, z相对控制, 旋转x, 旋转y, 旋转z, 夹爪目标]`。前六维会被控制器乘 scale；它们不是七个关节角，也不能直接当作实测米数。位置限幅是逐轴截断，不是对总位移长度限幅。

姿态一直朝下，四元数顺序是 XYZW，目标是 `[1, 0, 0, 0]`。教师不能选择旋转动作。朝下姿态纠偏与平移同时进行；位置命令不是孤立的直线运动保证。

`GRASP` 把夹爪目标改成 `−1`（闭合）；`RELEASE` 改成 `+1`（打开）；移动 token 沿用上次夹爪目标。两种夹爪 token 同样执行五帧位置保持和朝下姿态纠偏。所以 GRASP 不等于只动指头、机械臂绝对不动。`DONE` 不执行物理帧，只请求停止，不能自行宣告任务成功。

两个实际开局动作说明区别：A 第一帧七维动作约是 `[0.05, 0, 0, −0.11288, 0.16, 0.16, 1]`；B 是 `[0.24, 0, 0, −0.11288, 0.16, 0.16, 1]`。两者目标都沿 +X，开局也都在纠正姿态，夹爪保持打开。执行五帧后 A 实际 +X 约 0.612 mm，B 约 31.996 mm；不能把它们写成“执行了 25/120 mm”。

## 视频只有五秒，为何运行花了约十五分钟

每次尝试保存 250 个控制帧，50 Hz，所以仿真时间与视频是 5 秒。一个非 DONE token 执行五帧，即 0.1 秒仿真时间；每次尝试最多完成 50 次这样的决策。每控制帧内部有四个 0.005 秒物理子步，因此报告中的真实物理步数是 1000。

真实 HTTP 等待、重试期间，场景、物体、机械臂、目标计时器、动作历史都不推进。模型等十几秒，机器人在仿真里仍停在相同的一瞬间；拿到合法 token 才执行下一段 0.1 秒。所以 A 运行约 948.946 秒，B 约 909.656 秒，但各自只推进 5 秒仿真。

数据读取有一个容易误解的地方：250 帧超时的最后一次 `env.step` 会触发原生自动重置。记录器已在重置前保留最后动作帧与原生判定；网页的末尾位置必须来自 `native/trajectory.json` 的第 249 号帧，而不能从 `final_state.npz` 取。后者已是重置后的环境状态，连目标也已重新抽样，不代表这次轨迹中途目标漂移。最后决策 HTTP 等待前的目标仍是最初目标、剩余目标时间约 0.100004 秒。此外原件里的 `sim.physics_time_s` 字段实际为 0，展示时间应使用已核对的控制帧数/50 Hz 与物理步数×0.005 秒，不依赖这个字段。

A 的 `decision_000005` 与 `decision_000008` 首次请求各 35 秒超时，随后用相同请求体重试成功。前者总等待 48.533 秒，后者 45.163 秒。各占用两个请求，但各只执行了一次 token。两个重试不是额外物理动作。所有决策的冻结检查都有真实前后状态原件支持，16 个状态字段及帧计数、历史没有变化。

## A 与 B 各自发生了什么

**A：25 mm / hold5，首批未校准基线。** 平移步长和逐轴限幅都为 25 mm。50 次决策里有 47 次 `MV_FWD` 和 3 次 `MV_DOWN`。开局连续 42 次 FWD，用掉 4.2 秒仿真时间；首次 DOWN 在编号 42。未选择 GRASP、RELEASE 或 DONE，夹爪目标全程打开。记录到 250 帧/1000 物理步，原生 success=false，双指物理接触为零。

**B：120 mm / hold5，新诊断候选。** 在 B 启动前，根据 A 的实际前移偏小提出并登记一次可验证假设：增大步长与限幅，是否至少让前移投影翻倍。版本 `arena-online-step0.12-clamp0.12-hold5-v1`。这组不是历史研究成功的 120 mm / hold1，hold 仍为五帧。

B 的 50 次决策是 30 FWD、18 DOWN、1 GRASP、1 LEFT。前十次是 FWD，第 10 号决策改为 DOWN，第 11 号决策闭合夹爪。闭合时，夹爪参考点到方块中心约 675.9 mm，垂直高约 671.4 mm，没有物理接触，是一次过早空闭合。此后没有 RELEASE，夹爪目标保持闭合；模型继续用 FWD、DOWN 和一次 LEFT 调整，最终仍未接触方块、未成功。

这里的编号从零开始，网页可显示“第 12 次决策（decision_000011）”避免误读。视频时间区间也应按 50 Hz 解释，而不是 HTTP 墙钟时间。

## 怎样分析配对结果

先检查是不是可比较的一对：同一个开发开局 seed=42，任务、相机设置、教师型号、system/user 模板、固定朝下姿态、hold5、控制频率和 250 帧上限相同；16 个重置状态字段最大差值为零，实际 `native_run` 控制函数相同。两次的 RGB 像素哈希并不完全相同，所以不能说三图像素也一模一样。

再检查 B 的假设有没有在运行前写清楚。正式依据是 `diagnosis_before_b_v2.json`，在 B 预留与启动前已保存，包含 A 原件哈希、改哪两个参数、预期效果及比较方法。较早 v1 草稿曾错误计算跨轴指标，原件保留并明确更正，不能以 v1 当最终正确依据。

实际比较分两层：

- **整体 FWD 响应**：A 47 次 FWD 的沿指令轴位移中位数 8.687 mm，B 30 次为 35.334 mm，超过事先设定的两倍门槛 17.374 mm。
- **共同前十个 FWD**：相同重置状态和相同动作词前缀下，沿 +X 投影中位数 A 3.516 mm，B 40.452 mm（约 11.50 倍）；但偏离 X 轴的 YZ 位移长度中位数也从 0.927 mm 增到 10.311 mm。跨轴最大值 A 2.502 mm，B 44.262 mm。

随后检查反作用与实际任务：A 的 3/3 DOWN 都实际向上，B 为 17/18；沿所请求 −Z 的投影中位数分别为 −5.639 与 −38.678 mm，负值表示动作区间末尾比区间开头更背离该方向。**A 也已出现反向，不是 B 首次引入的新问题。** 两组均零接触、零成功。

所以小假设“前移会变大”成立，却不足以支持“大步长控制整体更好”。候选未采纳，不改变全局解释器默认参数。这是一个开发开局的配对案例验证，不是统计成功率提升，也不能把 A 全部 47 次 FWD 与 B 全部 30 次 FWD 当作状态完全相同的 77 个重复样本。两组后续视觉和历史不同，token 分布也不同；step/clamp 一起变化，不能单独归因给其中一项。

## 失败原因：哪些知道，哪些还不知道

**证据已经证明的事实：**

- 两次尝试均没有接触或搬动物体，原生成功信号为 false；因此不存在合格在线触觉示范。
- 动作解释器的 25 mm / hold5 基线尚未校准，目标位移与真实响应有明显差距。
- 多个 DOWN 区间实测末端向上，实际七维输入的 Z 控制是负值。问题不只是教师没选 DOWN；也不能说词表里的 DOWN 被直接写成了 +Z。
- B 有一次远离物体的空闭合，之后未 RELEASE。原件保留，由外部审计回执标记已知错误；不猜教师内部意图。
- B 的前移变大伴随更大跨轴偏移与不稳定方向响应，整个任务仍失败。

**有依据，但本次尚未验证的解释：**

- 固定朝下姿态纠偏、相对位姿 IK、关节控制与已有运动速度共同作用，可能让很短的五帧内实际运动偏离位置目标；例如 B GRASP 首帧只要求位置保持，却仍有较大姿态纠偏与末端移动。需要独立低层分析，才能判断哪个环节主导反向。
- 五帧是 0.1 秒，未必足以收敛到目标。token 结束就根据当前图重设下一目标；当动作响应未校准时，模型难以建立稳定的“选这个词，会去哪里”的对应关系。
- 开局场景图里的方块较小，腕部图主要看到夹爪与桌面；三图缺少深度、显式相机/轴标定、位移幅度数字，可能使模型难以判断距离和基座方向。不过没有模型解释或受控视觉对照，不能据此宣称模型一定把标记或方块认错。
- 只有五个移动词的历史，没有夹爪 token 或位置进度，可能限制跨轮动作结果跟踪。但这是合同限制，本次没有验证换上下文是否更好。
- 5 秒仿真/50 决策的预算约束让 A 在反复 FWD 后几乎没有时间下探和抓取。它限制了本次尝试的机会；但不能因此说扩时就会成功，因为本次还观察到实际 DOWN 响应反向。

**仍不能得出的结论：**

- 无法从这两次识别唯一根因，不能在没有验证时宣布 IK 的坐标系、四元数、关节映射或模型视觉中的某一项必然错误。
- 无法评价接触后的触觉策略能力：两次没有进入接触阶段。
- 无法推出模型通用抓取能力、统计失败率，或学生 TacJev 的任何能力。
- 没有自动“自进化”：没有更新模型参数，只有一次明确登记的解释器参数候选与对照。

## 历史成功脚本为什么只能作参考

研究封存前的 120 mm / hold1 成功属于几何脚本教师，它根据特权几何状态选择 token，且每个 token 只执行一帧。此次 B 是图像驱动在线模型、120 mm / hold5；决策来源、反馈周期均不同。历史结果可提示“本体与某种控制路径曾有任务可行性”，不能直接证明在线模型同参数成功，也不能与两次在线失败拼接成一次完成 rollout。研究分支、原件和预算保留，本次没有重开研究。
